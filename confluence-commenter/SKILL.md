# confluence-commenter —— 使用说明（给助手）

这个 skill 只有一个用途：核对完 Confluence 页面与当前代码之后，在页面底部
留一条简短评论，指出不一致。它**只能发评论**：不能改页面、不能删评论、
不发页面内评论。读取页面用另一个只读 skill（confluence-reader），读写分开、
令牌分开，不要混用。

脚本：`scripts/confluence_comment.py`（只用 Python 标准库）。配置在 skill
根目录的 `config.ini`（由 `config.ini.example` 复制填写）。所有命令都先读配置。

## 什么时候发评论

1. 先用 confluence-reader 读页面，再拿**当前代码**逐条核对。核对结论只有三种：
- 完全正确 → **什么都不做**，不发评论（verdict=correct 会被工具直接拒绝）；
- 完全错误 → 发一条评论，`--verdict wrong`；
- 有对有错 → 发一条评论，`--verdict partial`，点出哪些一致、哪些不一致。
2. **代码验证不了的内容不发评论**：业务规则本身对不对、外部系统的实际行为、
流程约定这类没有代码依据的事项，不在本 skill 的处理范围内。
3. 措辞保持中性：写「与当前代码实现不一致」，**不要**写「文档错误」「文档写错了」。
页面和代码谁对，最终由页面负责人判断，评论只负责把差异摆出来。

## 评论怎么写

- 最终评论由工具拼装：固定前缀 `` + 正文 + 固定落款
`（以上由 AI 依据当前代码核对生成{，代码版本：<code-ref>}；如有不同意见请直接回复本评论）`。
你只写**正文**，前缀和落款不用写、也不要自己仿造。
- 正文默认不超过 **300 个字符、5 行**；只写结论，不写细节，不贴代码块（会被拒绝）。
可以出现类名、配置项名这类短标识。
- 正文里**不要**出现敏感信息：IP 地址、带主机名的内网链接、邮箱、手机号、
身份证号、银行卡号、任何 `password=` / `token:` 形式的赋值、JDBC 连接串、私钥。
工具会扫描并拒绝发送，还会指出命中了哪条规则（命中内容打码显示）。
- 发评论时带上 `--code-ref`（分支名或提交号），落款里会自动带上代码版本。

正文模板（虚构的通用场景，照这个口径写）：

`--verdict wrong`（3–5 行）：

```
文档说单据提交后立即进入下一环节，代码里实际要等定时任务
跑完才流转；文档说的校验口径代码里也没有实现。
整页描述与当前代码实现不一致，请负责人确认以哪边为准。
```

`--verdict partial`（3–5 行）：

```
与代码核对：单据状态的流转顺序与代码一致。
不一致的是超时口径：文档写 30 分钟，代码里实际是 60 分钟；
文档提到的重试入口在代码里也已不存在。
请负责人确认超时口径是否需要随代码更新。
```

## 命令用法

```bash
# 1. 先测连接与认证
python scripts/confluence_comment.py check

# 2. 生成评论并检查（不会发送），把输出原样给用户确认
python scripts/confluence_comment.py preview <页面ID或URL> --verdict wrong|partial \
    --text "正文" [--code-ref 分支或提交号]
# 正文较长时用 --file 评论正文.md 代替 --text

# 3. 用户确认后才发送（必须带 --yes）
python scripts/confluence_comment.py send <页面ID或URL> --verdict wrong|partial \
    --text "正文" [--code-ref...] --yes

# 跟进同一页面：该页已有一条未结的本工具评论时，新评论会被拒；
# 确需补充时加 --followup，作为对自己那条评论的回复发出
python scripts/confluence_comment.py send <页面ID> --verdict partial --text "..." --followup --yes

# 查看已发评论的状态：未回复 / 有回复（列出回复人、时间、内容前 100 字）/ 页面已更新 / 评论已删除
python scripts/confluence_comment.py status [--page 页面ID]

# 查看本地发送日志
python scripts/confluence_comment.py log
```

## 硬性流程与注意事项

1. **先 preview，后 send。** 发送前必须先跑 preview，把 preview 的完整输出
给用户看、得到确认，再执行 `send --yes`。不要跳过确认直接发送；
`send` 不带 `--yes` 会被工具拒绝。
2. **认证失败（退出码 3）立即停下，把情况告诉用户，不要换方式重试。**
工具在认证失败时只请求 1 次、绝不自动重试；你也不要改用其他账号、
其他令牌或其他工具绕过去。网络错误是退出码 4，工具内部最多重试 1 次，
仍失败就停下报告。
3. 带 `` 前缀的评论是 AI 自己以前写的。以后再核对同一页面时，
**不得把这类评论当作证据或依据**——核对只认页面正文与当前代码。
4. 防误发是代码强制的，不要试图绕过：
- 同一页面同一内容发过就拒绝（幂等）；
- 同一页面有未结的本工具评论时拒绝新发，只能用 `--followup` 回复跟进；
- 单次运行最多发 10 条（config 可调）；同一批核对请在环境变量
`CONFLUENCE_W_RUN_ID` 里给这一批设一个固定值，计数才准；
- config 里的拒绝清单（空间、页面 ID、标题关键词）命中就拒绝，
这是用户特意排除的页面，不要换个说法再发。
5. 凭据只在 `config.ini` 或 `CONFLUENCE_W_*` 环境变量里，永远不要把令牌、
密码写进评论、日志或对话输出。
