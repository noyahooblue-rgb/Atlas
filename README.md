# specpeek

Markdown 规格人工审查辅助工具：扫描目录下的 `.md` 文件，为编号
（业务规则、验收标准、实现任务、外部规则、待确认项、发布前核查项）
建立定义与引用索引，做追溯检查与同号异义检查，生成单文件审查页，
并能按编号对比两个版本的差异。

只用 Python 标准库，Python 3.8+，Windows 与 Linux 都能运行；
输入文件按 UTF-8 读取（兼容 BOM），只读，不修改输入文件；
生成的 HTML 不引用任何外部 CDN、字体与脚本，断网可用。

## 安装运行

无需安装第三方包，克隆仓库后在仓库根目录运行：

```bash
python -m specpeek check examples
python -m specpeek html examples -o review.html
python -m specpeek diff 旧目录 新目录 -o diff.html
python -m unittest
```

`check` 有异常时退出码为非 0，可接入 CI；无异常时退出码为 0。
检查包括四类：被引用但找不到定义、定义了但从未被引用、覆盖
关系缺口、同号异义（同一编号多处定义且内容不同，给出各处位置）。

## 编号配置

默认配置在 `specpeek/default_config.json`，覆盖 R、AC、T、BDR、OI、PC
六类编号。自定义时传 `--config 配置文件路径`：

```bash
python -m specpeek check examples --config my-config.json
```

配置格式：`categories` 每项含 `id`、`name`、`pattern`（正则，不带捕获组）；
`coverage` 每项声明一对覆盖关系（`from` 源类别、`to` 目标类别、`label` 缺口文案）。
定义处识别方式：标题行、列表项开头、行首编号优先，表格首列次之。
表格行要成为定义，编号后紧邻的单元格必须是文本列（去掉全部编号
与分隔符后仍有内容）；编号后紧跟其他编号的行是追溯/引用行，不算
定义——这样追溯总表既不会抢走正式定义，也不会把罗列编号的列误当
成定义的短名。

短名（审查页里编号后括号中的简短名称）规则：

- 标题 / 列表 / 行首定义：去掉标题与列表标记、加粗记号和编号本身，
  取剩余正文的前若干字（`short_name_length`，默认 24）；
- 表格定义：默认取编号列之后第一个文本列；类别条目可带
  `short_name_column` 指定列，字符串为表头列名、整数为列序号
  （0 起，编号列为 0），指定列缺失或为空时回退默认规则。

同号异义白名单：配置顶层 `allow_duplicate_prefixes` 是前缀数组，
编号以任一前缀开头时，多处内容不同的定义不算异常（适合外部
编号体系里允许重复登记的段）。

覆盖语义：某一行同时出现源编号与目标类别编号时，视作一次追溯链接；
源编号若从未出现在任何这样的行里，即为覆盖缺口。

## 审查页

- 正文中每个编号显示为「编号（短名）」，鼠标悬停弹出定义处原文和位置，点击跳到定义清单；
- 顶部显示追溯检查的异常汇总；
- 每个定义可打勾标记「已审」并写审查意见，状态存在浏览器 localStorage（读写包在 try/catch 里），点「导出审查意见为 Markdown」可下载意见文件。

## 差异审查

```bash
python -m specpeek diff 旧目录 新目录            # 命令行文本输出
python -m specpeek diff 旧目录 新目录 -o diff.html
```

按编号对比两个版本：新增、删除、内容改变各列一组，内容改变的
给出旧文 / 新文对照（含两处位置），最后单列内容未变的编号数。
比较的是每个编号的正式定义（扫描认定的第一处），内容按空白
归一化后比较。适合「AI 改了一轮规格后，人只看变化」的场景。

## 规模测试

`tools/gen_scale_spec.py` 生成一套虚构规格（社区食堂订餐系统）：
两个版本各约 700 行（实测 719 / 720 行），含 60 条规则、20 条
验收标准、15 个任务且交叉引用齐全，`check` 无异常；新版本含
1 新增、1 删除、3 处内容改变。

```bash
python tools/gen_scale_spec.py 目标目录 --bench
```

本机实测（Python 3.12，进程内计时）：check 0.021 秒、html 生成
0.067 秒、diff 0.022 秒，均不超过 2 秒。

## 已知限制

- Markdown 渲染只覆盖标题、表格、列表、代码块与段落，不追求完整 CommonMark；
- 覆盖关系按「同行共现」判定，不做语义理解；
- 代码块内的编号不计入索引与引用；
- 表格定义要求编号后紧邻文本列，描述列不在编号后第二列的表格
  需要用 `short_name_column` 或调整表格结构；
- 同号异义与差异审查比较的是定义行原文（空白归一化后），不做
  语义层面的异同判断。
